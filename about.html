A bit about how I work.

I'm a full-stack developer working mostly in Blazor Server and .NET, based at Puncak Nilam Management Services Sdn. Bhd. (PNMS). MIRAR is a separate company under the same management. My manager hands me the projects and shares ideas along the way; the design, the code, the hosting and the upkeep are mine.

For PNMS and MIRAR I moved both companies off their old PHP sites on cPanel and rebuilt them in Blazor, public site and every admin system behind it: certificates, attendance, quizzes, surveys and an expert directory for MIRAR; services, insights, a PDPA readiness check and enquiries for PNMS.

I also built iSeliaIntel, the backend that collects news, regulatory updates and market data and feeds it to iSelia (a GRC platform I build with my manager, where the front panel and PDF tools are mine) and to MIRAR. Then there are three full builds: CareVentis, a heritage-therapy clinic with online booking; star8892, a private social network for STAR Ipoh's 1988–1992 batch; and Autumn Twilight, a web home for a Dragonlance text world inspired by the classic game. All of it is still in active development.

I like systems that hold up under real use: consistent service-layer patterns, admin tools that don't fight the people using them, audit logs and outboxes so nothing goes missing quietly, and code that's still readable after the third feature request changes the plan.

Standard stack across most of this: Blazor Server (.NET) with MudBlazor, MariaDB/MySQL with Entity Framework Core, hosted on Plesk at iWHost, behind Cloudflare, deployed from GitHub. I also work with Python, Flask, PHP and plain HTML when a project calls for it.

Languages and frameworks

The day-to-day.

  • C# and .NET 8–9: Blazor Server and Blazor Web Apps (static server rendering plus interactive pages), ASP.NET Core APIs and minimal endpoints, SignalR
  • MudBlazor 9, including custom brand themes and upgrades from older versions
  • HTML, CSS and vanilla JavaScript, including a rich-text editor and a draw.io-style flowchart editor with no libraries
  • Python and Flask, PHP

Data

Where it all lives.

  • MariaDB and MySQL with Entity Framework Core (Pomelo), DbContext factories, migrations and hand-written SQL scripts
  • In-memory caching with stampede protection and refresh-in-place
  • Background workers for scheduled jobs: snapshots, reminders, retention and email retries
  • Excel, CSV and PDF exports

Documents, feeds and integrations

Talking to everything else.

  • PDFs with QuestPDF and PdfSharpCore, Excel with ClosedXML, QR codes with QRCoder, images with SkiaSharp
  • Email with MailKit over SMTP, through an outbox with retries and leases
  • RSS and Atom ingestion, HTML scraping with HtmlAgilityPack, and market data APIs (Finnhub, Alpha Vantage, ExchangeRate-API, Yahoo Finance)
  • Calendar invites (.ics and Google Calendar), Cloudflare Turnstile, sitemaps and schema.org structured data

Security and privacy

Because these sites hold real people's data.

  • BCrypt passwords, lockouts, two-step sign-in by emailed code, step-up re-authentication and session re-checks on open Blazor pages
  • Rate limiting, honeypots and form timing, Content-Security-Policy and security headers, signed short-lived links
  • Insert-only audit logs with alerts and archiving
  • PDPA-minded design: consent records, retention and anonymisation jobs, data export and erase

Hosting and infrastructure

From domain to running site.

  • iWHost Plesk hosting on Windows and IIS: app pools, web.config, ASP.NET Core hosting fixes
  • Cloudflare DNS for every domain, including SPF, DKIM, DMARC and MX records for email deliverability
  • Cloudflare Workers as a reverse proxy in front of each site, forwarding the real visitor IP and country with a shared secret
  • GitHub Actions push-to-deploy to Plesk with Web Deploy and a post-deploy health check; Docker; Git

How I work

The habits behind the code.

  • Every admin system gets the same backbone: dashboard, audit log, visitor analytics, email outbox and exports
  • Track every useful bit of context: IP, country, device, referrer and campaign on visits and submissions
  • Design for failure: empty states instead of errors, fallbacks when the database or an API is down
  • Turn a short brief into a shipped, maintained feature, and suggest improvements along the way
