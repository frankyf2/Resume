star8892 is a private social network for the 1988–1992 batch of STAR (Sekolah Tuanku Abdul Rahman) in Ipoh, built around their reunion and for keeping the batch in touch after it. Members get a wall, live chat, events with RSVPs, a marketplace, a directory and games. Admins get a full back office to approve members, moderate and run the site.

The public side

What someone sees before they're approved.

Batch pages

The reunion, out in the open.

  • Home, About, Reunion, Batch Events, Stories, Get Involved, FAQ, Help, Contact and Report a Problem
  • Batch events marked up as schema.org events so search engines can list them; private meeting links are deliberately left out

Joining

Only the batch gets in.

  • Register, verify the email with a code, then wait for an admin to approve
  • Forgot-password and a forced change for temporary passwords

What members get

A small Facebook for one school batch.

Wall

Posts, comments and reactions.

  • Main wall and an announcements wall, pinned posts first
  • Event walls that only that event's attendees can see
  • Fast paging that fetches only what the page shows, with a short preview of the latest comments

Chat

Live, with no refreshing.

  • Direct messages, group chats and a chat for each event
  • Messages appear straight away on every open page, including the unread badge in the nav bar

Events

Plan it, RSVP to it.

  • Calendar, create an event, my events, and RSVPs

Marketplace

Buying and selling within the batch.

  • Create listings, save them, place orders and track orders received
  • Reminders for quiet listings, expiry after about 60 days, bumping, and a sold ribbon
  • Renamed listings and events keep their old links working

Games

Leaderboards for the reunion.

  • A catalogue of board, card, sport, digital and trivia games, for individuals or teams
  • Each game sets its own scoring rule: highest points, lowest points (like golf), or wins only

People

Finding each other.

  • Member directory and profiles, notifications, site-wide search that follows the same privacy rules as the pages, and account settings

The admin back office

Two levels, Admin and Super admin, and every action written to an audit log.

Members

Who's in.

  • Pending approvals, member management, admins and a super admin console

Content

What the batch sees.

  • Announcements, events and their RSVP lists, marketplace and games
  • Feed moderation: hide, restore or remove any post or comment
  • Site pages: edit the public copy, with the old text kept in the audit log so a bad edit can be restored

Data

Keeping a copy.

  • CSV exports and database backups, keeping only the newest few

Settings and audit

Running the site.

  • Site settings, maintenance mode and the full audit log

Under the hood

Mostly security, because it holds personal details of real people.

Sign-in

Hard to abuse.

  • BCrypt passwords and lockouts that can't get stuck on forever
  • Throttles on sign-up, code checks and password resets, counted per IP and per target, so nobody can hammer one account or bomb one inbox

Sessions that stay honest

A Blazor-specific problem.

  • Open pages re-check the session every few minutes, so a suspended, demoted or signed-out member loses access without reloading
  • Step-up: admins re-enter their password before destructive actions, remembered per session, not per user
  • Maintenance mode also stops pages that were already open

Accountability

Who did what.

  • An insert-only audit log; once a day, old rows are archived to a compressed monthly CSV before leaving the database
  • Optional alert emails to super admins when an admin is added or removed, or data is exported
