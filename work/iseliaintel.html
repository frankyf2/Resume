iSeliaIntel

What it is
The intelligence backend behind iSelia and MIRAR (formerly Vectris Intel)
My role
Design, build and maintenance
Status
In development
Stack
ASP.NET Core · Blazor Server · MudBlazor · EF Core · MariaDB · background workers

iSeliaIntel collects news and regulatory updates from RSS feeds and websites, tags and groups them, scores risk across domains, gathers market data, and serves all of it through one JSON API. iSelia's front panel and MIRAR's Daily Brief both read from it. Staff run it from a set of ops screens, so adding a new source or a new calendar column is a form, not a deploy.

The pipeline

One background worker runs the whole cycle, in order, so each step works on fresh data from the step before.

Ingestion

RSS, Atom and websites.

  • RSS and Atom feeds parsed into one common entry format, with images pulled out of each item
  • Duplicates dropped using SHA-256 fingerprints, checked in memory against everything already stored

One scraper for every regulator

New sources without new code.

  • A single generic HTML scraper for any page that is a list of date, title and link, such as press releases and notices
  • Selectors are stored per source as JSON and edited in Scraper Ops, so adding a site is a new row, not a deploy
  • This is what scrapes regulatory sources for both MIRAR and iSelia

Tagging and compliance

Turning headlines into signals.

  • A rule engine tags each item (for example Cybersecurity, GeoRisk, Market) with an importance score
  • Items are mapped to compliance standards and their controls
  • Related stories are grouped by comparing normalised titles

Risk scoring

From tags to an index.

  • Tags map to risk domains with weights; recent risk items add weighted signals to each domain and to a composite risk index
  • Snapshots at 09:00 and 18:00 Malaysia time, one per slot, so a manual re-run never creates duplicates
  • A history endpoint that powers the trend charts on iSelia

Calendar events

What matters today.

  • Today's tagged items are promoted to calendar events by rule: always-promote tags, Risk and Compliance sources, or a high enough importance score
  • Calendar columns come from a mapping table, so a new column is one row

Market data

Indices, futures and FX.

  • Pulled every few minutes from Finnhub, Alpha Vantage, ExchangeRate-API and Yahoo Finance, plus intraday series
  • Works around Yahoo's quirks: a cookie and crumb handshake, futures and regular symbols fetched separately, and a fallback endpoint for any symbol that comes back empty

Lifecycle

Keeping the store tidy.

  • Old items cleaned up each cycle, then the shared cache refreshed

The ops screens

A small Blazor admin for the people who run it.

Sources

What gets collected.

  • Feed Ops for RSS sources, Scraper Ops for scraped sites, Market Ops for market symbols and providers

Rules and scores

How it's interpreted.

  • Risk Keywords for tagging rules, Risk Ops with the trend chart, Compliance Ops for standards and controls, Event Ops for the calendar

Reading views

Checking the output.

  • News and intelligence views, and a market page, so staff can see exactly what the sites will show

Under the hood

Most of the work here is making it fast and making it actually run.

Performance

Why the feeds got quicker.

  • A single shared cache in front of every read, used by iSelia, MIRAR and the admin pages alike
  • The cache is now refreshed in place instead of being cleared and left for the next visitor to rebuild
  • Tagging rules, tags and compliance controls are loaded once per cycle instead of once per item, which removed thousands of database round-trips

Fixes that mattered

Things that were quietly broken.

  • Scraped sources were being parsed as RSS, failing silently every cycle; the scraper now actually runs in production
  • Every service moved to the same DbContext factory pattern

API

One contract for two sites.

  • 34 endpoints for news, intelligence by tag, market data, risk scores and history, calendar events and their mappings
  • Seed endpoints to set up the domain and calendar mappings on a fresh database
